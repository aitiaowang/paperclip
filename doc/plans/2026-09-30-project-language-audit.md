# 全项目前端语言检查与第二轮修复

用户报告搜索页仍整页英文，要求检查整个项目。沿用已有 i18next/react-i18next 和组织菜单中的全局语言选择，不引入自动 DOM 替换或新翻译依赖。

## 排查方法

- 新增 `scripts/check-i18n-coverage.cjs`，按 AST 扫描 `ui/src` 生产代码及可能贡献界面的 packages 文件，排除测试、fixture、示例和开发展示入口；按路由、组件、日期格式器和动态枚举分类。
- 扫描结果是待复核清单，不是确认缺陷数量或翻译完成率。默认输出 `tmp/i18n-audit.json`，可以使用 `--output` 指定位置。
- 单独检查 `ui/index.html` 的模块加载失败/超时恢复提示，这部分不能依赖未加载成功的应用模块。

## 本轮修复范围

- 搜索页、分类、筛选、排序、搜索结果来源、零结果恢复、命令面板及手机分类选择。
- 组织常规设置、个人资料、实例常规与实验设置、设置导航及直接依赖的策略选择控件。
- 收件箱工具栏、视图、分组、排序、列设置、空状态、受阻原因、归档/撤销、任务行提示。
- 员工列表与组织图的新旧界面、内置员工标记、团队目录与安装向导。
- 项目列表、新建项目与仓库选择；目标列表、详情、属性、新建目标及层级展示。
- 共用状态徽标、状态图标、收藏/加入/退出操作、侧边浮层关闭标签、金额周期/日期/相对时间显示。
- 启动加载/失败/等待恢复提示，以及开发服务重启提醒。

所有显示翻译保留原有 API 枚举、路由、搜索语法、用户名称、描述、仓库信息和执行行为。真实表单/筛选回归覆盖双向切换、草稿保留、选中项保留及发送原始业务值。

## 验证与限制

- 前端类型检查、构建、相关组件与页面测试、翻译键及占位符校验。
- 浏览器实测搜索页中英双向切换、手机分类选项及刷新后的语言保留。
- 设计 token 检查仍有既有的 109 处违规；逐条对比 HEAD，违规源码行均未由本轮新增或修改。
- 本轮未改后端契约、数据库或调度功能，未运行整个 monorepo 的后端测试、全仓类型检查或全仓构建；不能据此前端检查声称全仓通过。

## 明确未完成的范围

全项目检查已覆盖约定的生产前端范围，但全项目翻译尚未完成。Apps/连接器、Skills、Secrets、任务/员工/项目复杂详情、聊天、流水线及插件仍有大量系统文案待逐项迁移。第三方与用户内容应保留来源原文；内置目录内容需按稳定标识做展示翻译。

`utils` 中的格式器现在按当前语言格式化；未订阅语言变化的旧调用组件，仍需要逐个接入后才能保证不刷新就重算日期。错误边界与第三方服务返回的原始诊断也需要独立处理，不能把日志原文机械翻译。

后续按 AST 清单逐业务模块闭环：页面、详情、弹窗、空/错/加载态、移动布局、中文与英文、未保存输入/业务值回归。不能仅凭一个文件存在 `useTranslation` 就认定整个模块已完成。
