# 创建员工流程中英文适配

## 问题与范围

用户截图中的员工列表已显示中文，但创建员工弹窗的名称、执行器两步仍为硬编码英文。本轮沿用全局语言资源，覆盖创建路径实际可达的账号连接、配置、运行验证、完成提示及外部员工邀请。

## 实施约束

- 使用现有 `useTranslation` 订阅语言，保持唯一全局语言入口。
- 用户姓名、账号与连接名称、密钥、命令、服务端诊断原文、API 枚举保持原值。
- 语言切换不得清空输入、重启登录、重新创建员工、重新执行运行测试或扩大授权。
- Codex、Claude Code 等产品名称保留官方名称。
- 共享配置表单仅修改此创建路径直接使用的登录与模型选择组件，避免扩大到无关配置功能。

## 验证计划

1. 用真实语言资源复现名称向导仍英文；双向切换并验证名称、执行器选择与提交原值。
2. 检查连接密钥输入、邀请参数、配置草稿和异步错误显示的切换与保留。
3. 合并词条前验证中英文键集合、插值占位符及前缀一致。
4. 运行相关测试、UI 类型检查及生产构建。
5. 浏览器核对截图中的弹窗和下一步，保留中文，不创建真实员工或启动登录。

## 验证结果

- 名称及执行器向导回归先红后绿：1 项通过，覆盖双向切换、姓名和选择保留以及原始执行器标识提交。
- 连接、邀请及直接依赖：5 文件、45 项通过。
- 创建设置与密钥选择：2 文件、47 项通过。
- 登录及模型选择新增切换回归：5 项通过；既有配置表单与本地登录回归：3 文件、110 项通过。
- 最新 UI 类型检查及生产构建通过；差异空白检查通过。只验证本轮前端相关范围，未运行全仓库后端套件。
- 中英文资源增补 300 对词条，合并前检查键集合与插值占位符一致。
- 浏览器中确认名称和执行器两步显示中文。验证过程中未创建员工或发起真实登录。
- 后续发现本地数据库和服务已停止，恢复原 PostgreSQL 数据目录和 `tmp/paperclip-dev` 实例配置；健康检查返回正常，已有数据保持不变。
